### Мотивация
Постоянно увеличивающаяся нагрузка на сервисы компании "Александрит" приводит к техническим сбоям, которые, в свою очередь, отрицательно влияют на пользовательский опыт клиентов, партнеров и специалистов компании:
- поступают жалобы от клиентов на потерю или долгое изготовление заказов
- от операторов MES участились сообщения о том что dashboard'ы стали грузиться очень медленно
- пользователи public API так же постоянно отправляют отчеты о сбоях в работе API и потере информации о заказах

Все это приводит к финансовым и репутационным потерям компании.

На данный момент информация о причинах тех. проблем носит исключительно предположительный характер. Работа по исправлению проблем может быть эффективно спланирована только при наличии достоверных данных о состоянии системы во время работы и причинах сбоев.

Именно с этой целью необходимо внедрить систему мониторинга, которая в режиме реального времени будет собирать метрики о состоянии системы. Анализ этих метрик позволить выявить модули, которые не справляются с нагрузкой, дают большой процент ошибок или выполнение которых занимает больше планируемого времени.

Все это позволит оперативно реагировать на возникающие инциденты, быстро устранять ошибки и выстроить грамотную стратегию глобальных изменений системы с целью повышения производительности, отказоустойчивости и масштабируемости. 

### Выбор подхода к мониторингу
Предлагается использовать смешанный подход к мониторингу:
- для API сервисов - используем RED
- для БД, RabbitMQ, File storage - подход "Четыре золотых сигнала"

### Метрики
- Internet shop, CRM, MES
  - RPS - измерение нагрузки трафика и выявление аномалий (метки service, url_path, method)
  - RPS per user - выявление аномальной активности пользователя (метки service, url_path, method)
  - Number of HTTP 500 - обнаружение ошибок (метки service, url_path, method)
  - Response time - отслеживание скорости работы системы (метки service, url_path, method)


- Shop DB, MES DB
  - Memory Utilisation - определение границ ресурсных ограничений (метки service, instance_id) 
  - Number of connections - определение нагрузки на БД (метки service, instance_id)
  - Size of instance - определение размера БД (метки service, instance_id)
  - CPU % - контроль потребления ресурсов (метки service, instance_id)


- File Storage
  - Size of S3 storage - контроль потребления ресурсов


- RabbitMQ
  - Number of message in flight - количество сообщений в очереди (насыщенность)
  - Number of dead-letter-exchange letters - необработанные сообщения

### План действий
- Развернуть Prometheus

- Развернуть и настроить визуализацию в Grafana
- Настроить dashboards в Grafana
- Настроить alerting в Grafana
